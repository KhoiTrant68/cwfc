# SD3-backbone track (real/flow_sd3.py, real/eval.py --backbone sd3): a
# pretrained flow-matching (rectified-flow) transformer + ControlNet, used to
# replace the from-scratch UNetVelocity so the G4 lambda/kNN mechanism runs
# on top of an internet-scale image prior instead of a ~2000-crop pool. Needs
# a GPU with real headroom (Colab Pro/Pro+, rented A100-class) -- not
# feasible on Kaggle's free 2xT4 tier for anything beyond a smoke test.
#
# Pinned (not >=), and not 0.31.0 either (tried first, see below):
# - Newer diffusers releases (roughly 0.33+, alongside the ACE-Step audio
#   model) added attention_dispatch.py, which registers a FlashAttention-3
#   custom op at import time via torch._library.custom_op; on many torch
#   builds that registration itself raises (infer_schema ValueError on the
#   op's own signature), breaking `import diffusers` before any of our code
#   runs. 0.32.2 predates that module.
# - 0.31.0 (SD3.5's release) added `dual_attention_layers` to
#   SD3Transformer2DModel's config but SD3ControlNetModel.__init__ wasn't
#   updated in that same release to accept it; from_transformer() copies the
#   transformer's full config into `cls(**config)`, so building a ControlNet
#   from a plain SD3-medium transformer (dual_attention_layers=() but still
#   present as a key) raises `TypeError: unexpected keyword argument
#   'dual_attention_layers'` regardless of checkpoint. Fixed by 0.32.2.
diffusers==0.32.2
#
# transformers also pinned: recent releases refactored checkpoint loading
# to go through core_model_loading/sharding_utils, which imports DTensor
# from torch.distributed.tensor (the newer public location) -- on torch
# builds where DTensor still lives under the older torch.distributed._tensor
# path, that import fails before any model code runs. 4.44.2 predates that
# refactor and is a well-tested pairing with diffusers 0.31.0 for SD3.
transformers==4.44.2
#
# The rest of this block is pinned together as one known-working set for the
# diffusers==0.31.0 / transformers==4.44.2 pair above -- leaving any one of
# these unpinned lets pip's resolver pull today's latest release of just
# that package, which is exactly how the last few rounds of import errors
# happened (each fix pinned the package that had just broken, while the
# next-newest unpinned one broke next). Bump this whole block together, not
# one line at a time, if a future diffusers/transformers upgrade is needed.
accelerate==0.34.2
sentencepiece==0.2.0
huggingface_hub==0.25.2
tokenizers==0.19.1
protobuf==4.25.5
